## 3. Union & Intersection Types

### ✅ Union Types `|`

A union type means a value can be **one of several types**. TypeScript only lets you use members that exist on **every** type in the union without narrowing first.

```ts title="index.ts"
type ID = string | number;

function printId(id: ID) {
  console.log(id); // ok — console.log accepts anything
}

printId("abc"); // ok
printId(123);   // ok
```

#### Narrowing a union

Before accessing type-specific members, you must **narrow** to one branch:

```ts title="index.ts"
function format(value: string | number): string {
  if (typeof value === "string") {
    return value.toUpperCase(); // string branch
  }
  return value.toFixed(2); // number branch
}
```


### ✅ Intersection Types `&`

An intersection type combines multiple types — a value must satisfy **all** of them simultaneously.

```ts title="index.ts"
type Named = { name: string };
type Aged = { age: number };

type Person = Named & Aged;

const person: Person = { name: "Atik", age: 30 }; // must have both
```

#### Intersection with functions / conflicts

```ts title="index.ts"
type A = { id: number; label: string };
type B = { id: number; active: boolean };

type AB = A & B;
// { id: number; label: string; active: boolean }

// Conflicting types produce never
type C = { id: number };
type D = { id: string };
type CD = C & D; // id: never — can't be both number and string
```


### ✅ Union vs Intersection

| | Union `\|` | Intersection `&` |
|---|---|---|
| Meaning | One OR the other | All of them combined |
| Value must satisfy | At least one type | All types |
| Member access | Only shared members | All members from all types |
| Use case | Flexible inputs | Combined / composed types |

```ts title="index.ts"
type A = { x: number };
type B = { y: number };

type AorB = A | B;        // has x OR y — only shared members accessible directly
type AandB = A & B;       // has x AND y — both accessible
```


### ✅ Discriminated Unions

A **discriminated union** (also called tagged union) is a union where every member has a common property — the **discriminant** — with a unique literal type. TypeScript uses the discriminant to narrow to the exact type.

```ts title="index.ts"
type Circle   = { kind: "circle";   radius: number };
type Square   = { kind: "square";   side: number };
type Triangle = { kind: "triangle"; base: number; height: number };

type Shape = Circle | Square | Triangle;
```

The `kind` property is the discriminant — each type has a unique literal value.

#### Narrowing with discriminant

```ts title="index.ts"
function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2; // shape is Circle here
    case "square":
      return shape.side ** 2;             // shape is Square here
    case "triangle":
      return (shape.base * shape.height) / 2; // shape is Triangle here
  }
}
```

#### Exhaustiveness check with `never`

If you add a new member to the union but forget to handle it, TypeScript will error:

```ts title="index.ts"
function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":   return Math.PI * shape.radius ** 2;
    case "square":   return shape.side ** 2;
    // forgot "triangle"
    default:
      const _exhaustive: never = shape; // Error — Shape is not assignable to never once Triangle is left over
      return _exhaustive;
  }
}
```

This pattern catches missing cases **at compile time**: TypeScript never flags a missing `switch` case by itself, but once `shape` reaches the `default` branch it's narrowed to whatever member is left unhandled (`Triangle` here) — not `never` — so assigning it to a `never`-typed variable is what produces the error.

#### Discriminated unions for state modelling

```ts title="index.ts"
type RequestState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error";   error: string };

function render<T>(state: RequestState<T>) {
  switch (state.status) {
    case "idle":    return "Waiting...";
    case "loading": return "Loading...";
    case "success": return state.data;   // data is available here
    case "error":   return state.error;  // error is available here
  }
}
```

Discriminated unions are the go-to pattern for modelling **finite states**, **action types**, and **API responses** in TypeScript.
