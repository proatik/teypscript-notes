## 9. Enums

### ✅ Numeric Enums

The default enum — members are assigned **auto-incrementing numbers** starting from `0`.

```ts
enum Direction {
  Up,    // 0
  Down,  // 1
  Left,  // 2
  Right, // 3
}

console.log(Direction.Up);    // 0
console.log(Direction[0]);    // "Up" — reverse mapping
```

You can set a custom starting value:

```ts
enum StatusCode {
  Ok       = 200,
  NotFound = 404,
  Error    = 500,
}
```

#### Reverse mapping — a numeric enum pitfall

Numeric enums generate a **bidirectional** mapping object at runtime:

```ts
// Generated JavaScript:
var Direction;
(function (Direction) {
    Direction[Direction["Up"] = 0] = "Up";
    Direction[Direction["Down"] = 1] = "Down";
})(Direction || (Direction = {}));
```

This means `Direction[0]` gives `"Up"` — which can cause unexpected behaviour and is one of the reasons numeric enums are considered problematic.


### ✅ String Enums

Members are assigned **explicit string values**. No reverse mapping — safer and more predictable.

```ts
enum Status {
  Pending  = "PENDING",
  Active   = "ACTIVE",
  Inactive = "INACTIVE",
}

console.log(Status.Pending); // "PENDING"
// No reverse mapping — Status["PENDING"] is undefined
```

String enums are preferred over numeric when the values need to be readable (e.g. API responses, logging).


### ✅ `const enum`

A `const enum` is **fully erased at compile time** — TypeScript inlines the values directly at every usage site. No runtime object is generated.

```ts
const enum Direction {
  Up    = "UP",
  Down  = "DOWN",
  Left  = "LEFT",
  Right = "RIGHT",
}

const move = Direction.Up;

// Compiled JavaScript:
const move = "UP"; // inlined — no Direction object exists
```

**Benefits:** Zero runtime overhead, smaller bundle.

**Pitfall:** `const enum` values cannot be safely used across module boundaries when using transpilers that compile one file at a time (Babel, esbuild, SWC) — the transpiler can't see the values to inline them, causing runtime failures. Enable `isolatedModules: true` to catch this at compile time.

```ts
// another-file.ts
export const enum Foo { A = 1 }

// my-file.ts — with isolatedModules: true
import { Foo } from "./another-file"; // Error — cannot import const enum from another file
const x = Foo.A;
```

Avoid `const enum` in shared libraries or when using transpilers other than `tsc`.


### ✅ Enum Pitfalls

#### 1. Numeric enums accept any number

```ts
enum Direction { Up = 0, Down = 1 }

function move(dir: Direction) {}

move(999); // No error! — TypeScript allows any number for numeric enums
```

String enums don't have this problem:

```ts
enum Status { Active = "ACTIVE" }

function set(s: Status) {}
set("ACTIVE"); // Error — must use Status.Active
```

#### 2. Runtime overhead

Every non-`const` enum generates a JavaScript object. In performance-sensitive code or large bundles this adds up.

#### 3. `--erasableSyntaxOnly` (TS 5.8+)

TypeScript 5.8 introduced this flag to error on non-erasable syntax including regular (non-const) enums, pushing teams toward modern alternatives.

```ts
// With erasableSyntaxOnly: true
enum Foo { A, B } // Error — use a union or as const object instead
```


### ✅ Enum Alternatives (Modern TypeScript)

The TypeScript community increasingly favors alternatives over enums for most use cases.

#### Union of string literals

```ts
type Direction = "UP" | "DOWN" | "LEFT" | "RIGHT";

function move(dir: Direction) {}

move("UP");    // ok
move("JUMP");  // Error
```

Zero runtime overhead, fully type-safe, no pitfalls.

#### `as const` object

Use when you need an iterable set of values or want to reference the type from the object:

```ts
const Direction = {
  Up:    "UP",
  Down:  "DOWN",
  Left:  "LEFT",
  Right: "RIGHT",
} as const;

type Direction = typeof Direction[keyof typeof Direction];
// "UP" | "DOWN" | "LEFT" | "RIGHT"

Object.values(Direction); // ["UP", "DOWN", "LEFT", "RIGHT"] — iterable

function move(dir: Direction) {}
move(Direction.Up); // ok
move("UP");         // ok — same as Direction.Up
```

#### Quick comparison

| | Enum | Union `\|` | `as const` object |
|---|---|---|---|
| Runtime object | ✅ (overhead) | ❌ | ✅ (plain JS object) |
| Iterable | ✅ | ❌ | ✅ |
| Reverse mapping | ✅ numeric only | ❌ | ❌ |
| Type-safe | ⚠️ numeric: weak | ✅ | ✅ |
| Works with `isolatedModules` | ⚠️ const enum doesn't | ✅ | ✅ |
| Modern recommendation | ⚠️ | ✅ | ✅ |
