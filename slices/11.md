## 11. Modules & Declaration Files

### ✅ ES Modules in TypeScript

TypeScript uses the same ES module syntax as JavaScript — `import` / `export`. TypeScript adds type-only imports and exports on top.

```ts
// Named export
export function add(a: number, b: number): number {
  return a + b;
}

// Default export
export default class UserService { /* ... */ }

// Named import
import { add } from "./math";

// Default import
import UserService from "./user-service";

// Import everything
import * as math from "./math";
math.add(1, 2);
```

#### Type-only imports & exports

Use `import type` / `export type` for types that are **erased at compile time** and never exist in the JavaScript output.

```ts
import type { User } from "./types";
export type { User };
```

With `verbatimModuleSyntax: true` (TS 5.0+), TypeScript enforces this — any import used only as a type must use `import type`. This prevents bundler issues and makes the boundary explicit.

```ts
// verbatimModuleSyntax: true
import { User } from "./types";     // Error if User is only used as a type
import type { User } from "./types"; // Correct — erased in output
```


### ✅ `.d.ts` Declaration Files

A `.d.ts` file contains **only type information** — no implementation. It tells TypeScript the shape of values from JavaScript files or external packages.

```ts
// math.d.ts
export declare function add(a: number, b: number): number;
export declare const PI: number;
```

The companion `math.js` file contains the actual implementation. TypeScript uses the `.d.ts` for type checking only.

#### When are they generated?

With `declaration: true` in `tsconfig`, TypeScript automatically generates `.d.ts` files from your `.ts` source — essential when publishing a package.

```json
{
  "compilerOptions": {
    "declaration": true,
    "declarationMap": true  // generates .d.ts.map for source navigation
  }
}
```


### ✅ `declare` Keyword

`declare` tells TypeScript that something exists **without providing an implementation**. Used in declaration files and for ambient declarations.

```ts
// Declare a global variable (defined at runtime, e.g. by a script tag)
declare const __VERSION__: string;

// Declare a global function
declare function fetch(url: string): Promise<Response>;

// Declare a module
declare module "*.svg" {
  const content: string;
  export default content;
}

// Declare a namespace
declare namespace MyLib {
  function greet(name: string): void;
  let version: number;
}
```

`declare` has zero impact on the JavaScript output — it's purely a type-level annotation.


### ✅ `@types` Packages

Many JavaScript libraries don't include TypeScript types. The **DefinitelyTyped** project maintains community-written declaration files published as `@types` scoped packages.

```bash
npm install --save-dev @types/lodash
npm install --save-dev @types/node
```

Once installed, TypeScript automatically picks up the types — no import needed.

```ts
import _ from "lodash"; // types from @types/lodash
_.chunk([1, 2, 3, 4], 2); // fully typed
```

Modern packages (React 18+, Next.js, etc.) ship their own types — no separate `@types` package needed.

#### Type lookup order

TypeScript resolves types in this order:
1. Bundled types in the package (`types` / `typings` field in `package.json`)
2. `@types/<package>` in `node_modules/@types`
3. `typeRoots` / `types` in `tsconfig`


### ✅ Module Augmentation

Extend an existing module's types **without modifying the source** — useful for adding properties to third-party types.

#### Augmenting a module

```ts
// Extend Express's Request type
import "express";

declare module "express" {
  interface Request {
    user?: { id: string; role: string };
  }
}

// Now TypeScript knows about req.user in your Express handlers
app.get("/", (req, res) => {
  console.log(req.user?.id); // typed
});
```

#### Augmenting global types

```ts
// global.d.ts
declare global {
  interface Window {
    analytics: Analytics;
  }

  interface Array<T> {
    last(): T | undefined;
  }
}

export {}; // makes this file a module (required for declare global)
```

#### Augmenting with `interface` only

Module augmentation only works with `interface` — not `type`. This is one of the key reasons to use `interface` when defining shapes in libraries.


### ✅ `verbatimModuleSyntax` (TS 5.0+)

Replaces the deprecated `--importsNotUsedAsValues` and `--preserveValueImports` flags. Enforces a simple rule: **what you write is what appears in the output**.

- Imports without `type` → kept in JS output
- Imports with `type` → erased

```ts
// Input (TypeScript)
import { type User, createUser } from "./user";

// Output (JavaScript)
import { createUser } from "./user"; // type import erased
```

This makes TypeScript output predictable and compatible with ESM-native bundlers (Vite, esbuild, etc.).
