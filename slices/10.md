## 10. Advanced Types

### ✅ Mapped Types

Mapped types create a new type by **iterating over the keys** of an existing type and applying a transformation.

```ts title="index.ts"
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

type Partial<T> = {
  [K in keyof T]?: T[K];
};
```

`[K in keyof T]` iterates over all keys of `T`. `T[K]` is the value type at each key. (These reimplement the built-in `Readonly`/`Partial` from the Utility Types chapter — shown here to illustrate the mechanism, not as code you'd actually declare alongside the real ones.)

#### Adding / removing modifiers

Use `+` to add and `-` to remove modifiers like `readonly` and `?`:

```ts title="index.ts"
// Remove readonly from all properties
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// Remove optional from all properties
type Required<T> = {
  [K in keyof T]-?: T[K];
};
```

#### Remapping keys with `as`

Rename keys during mapping using `as` and template literal types:

```ts title="index.ts"
type Getters<T> = {
  [K in keyof T as `get${Capitalize<K & string>}`]: () => T[K];
};

type User = { name: string; age: number };
type UserGetters = Getters<User>;
// { getName: () => string; getAge: () => number }
```

#### Filtering keys

Use `never` to exclude keys:

```ts title="index.ts"
// Keep only string-valued keys
type StringKeys<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

type User = { name: string; age: number; email: string };
type StringFields = StringKeys<User>;
// { name: string; email: string }
```


### ✅ Conditional Types

A conditional type chooses between two types based on a condition — like a ternary for types.

```ts title="index.ts"
type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<string>; // "yes"
type B = IsString<number>; // "no"
```

#### Practical examples

```ts title="index.ts"
// Unwrap array element type
type ElementType<T> = T extends (infer E)[] ? E : never;

type A = ElementType<string[]>;  // string
type B = ElementType<number[]>;  // number
type C = ElementType<string>;    // never — not an array

// Extract message from object
type MessageOf<T> = T extends { message: infer M } ? M : never;

type Email = { message: string };
type D = MessageOf<Email>; // string
```

#### Distributive conditional types

When `T` is a **naked type parameter** (not wrapped), conditional types **distribute over unions**:

```ts title="index.ts"
type ToArray<T> = T extends any ? T[] : never;

type A = ToArray<string | number>;
// string[] | number[]  — distributed over each union member
```

To prevent distribution, wrap in a tuple:

```ts title="index.ts"
type ToArrayNonDist<T> = [T] extends [any] ? T[] : never;

type B = ToArrayNonDist<string | number>;
// (string | number)[]  — treated as one type
```


### ✅ `infer`

`infer` declares a **type variable** inside a conditional type that TypeScript fills in during type resolution — pattern matching for types.

```ts title="index.ts"
// Extract return type of a function
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type A = ReturnType<() => string>;         // string
type B = ReturnType<(x: number) => void>;  // void
```

```ts title="index.ts"
// Extract first element of a tuple
type Head<T extends any[]> = T extends [infer H, ...any[]] ? H : never;

type A = Head<[string, number, boolean]>; // string
```

```ts title="index.ts"
// Extract promise value (recursive)
// The built-in Awaited<T> in TS 4.5+ does this — shown here to illustrate the infer pattern
type DeepAwaited<T> = T extends Promise<infer U> ? DeepAwaited<U> : T;

type A = DeepAwaited<Promise<Promise<string>>>; // string
```

```ts title="User.ts"
class User {
  constructor(public name: string, public age: number) {}
}
```

```ts title="index.ts"
// Extract constructor parameter types
type ConstructorParams<T> = T extends new (...args: infer P) => any ? P : never;

type Params = ConstructorParams<typeof User>; // [name: string, age: number]
```


### ✅ Template Literal Types (TS 4.1+)

Build string types dynamically by combining string literals — like template literals in values, but at the type level.

```ts title="index.ts"
type Greeting = `Hello, ${"World" | "TypeScript"}!`;
// "Hello, World!" | "Hello, TypeScript!"
```

#### Building event names

```ts title="index.ts"
type EventName<T extends string> = `on${Capitalize<T>}`;

type ClickEvent = EventName<"click">;   // "onClick"
type ChangeEvent = EventName<"change">; // "onChange"
```

#### CSS property types

```ts title="index.ts"
type Side = "top" | "bottom" | "left" | "right";
type Padding = `padding-${Side}`;
// "padding-top" | "padding-bottom" | "padding-left" | "padding-right"
```

#### Key remapping with template literals

```ts title="index.ts"
type Setters<T> = {
  [K in keyof T as `set${Capitalize<K & string>}`]: (value: T[K]) => void;
};

type User = { name: string; age: number };
type UserSetters = Setters<User>;
// { setName: (value: string) => void; setAge: (value: number) => void }
```

#### Built-in string manipulation types

```ts title="index.ts"
type A = Uppercase<"hello">;     // "HELLO"
type B = Lowercase<"HELLO">;     // "hello"
type C = Capitalize<"hello">;    // "Hello"
type D = Uncapitalize<"Hello">;  // "hello"
```


### ✅ Recursive Types

A type that references itself. Useful for modelling nested or tree-shaped data.

```ts title="index.ts"
// JSON value type
type JsonValue =
  | string
  | number
  | boolean
  | null
  | JsonValue[]
  | { [key: string]: JsonValue };

const data: JsonValue = {
  name: "Atik",
  scores: [1, 2, 3],
  meta: { active: true, tags: ["ts", "js"] },
};
```

```ts title="index.ts"
// Deep readonly — handles arrays, functions, and objects correctly
type DeepReadonly<T> = T extends (infer U)[]
  ? ReadonlyArray<DeepReadonly<U>>
  : T extends Function
  ? T
  : T extends object
  ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
  : T;
```

**Why the `Function` branch matters:** without it, the `T extends object` branch also catches function types (functions are objects in TS) and maps over their keys — which produces a type with no call signature at all. Applying the naive version to an everyday shape like `{ name: string; onClick: () => void }` compiles fine, but the resulting `onClick` becomes uncallable (`TS2349: This expression is not callable`). Checking `T extends Function` first and returning `T` as-is preserves the call signature while still recursing into everything else. This is the same special-case-functions-first approach libraries like `ts-essentials` use for their `DeepReadonly`.

```ts title="index.ts"
// Nested menu structure
type MenuItem = {
  label: string;
  href?: string;
  children?: MenuItem[]; // self-reference
};
```

TypeScript 5.x compiles recursive types faster than previous versions, but very deeply recursive types (deep path access, recursive template literals) can still hit "Type instantiation is excessively deep" limits. Keep recursion reasonably bounded.


### ✅ Branded / Nominal Types

TypeScript's type system is **structural** — two types with the same shape are interchangeable, even when they mean different things:

```ts title="index.ts"
type UserId = string;
type OrderId = string;

function getUser(id: UserId) {}

const oid: OrderId = "order_123";
getUser(oid); // no error — both are just `string` to TypeScript
```

A **brand** (a.k.a. nominal typing workaround) intersects the real type with a unique, uninhabited tag property so two otherwise-identical types stop being assignable to each other:

```ts title="index.ts"
type UserId = string & { readonly __brand: unique symbol };
type OrderId = string & { readonly __brand: unique symbol };

function createUserId(id: string): UserId {
  return id as UserId; // the one place a raw string becomes a UserId
}

function getUser(id: UserId) {}

const uid = createUserId("u1");
getUser(uid);   // ok
getUser("u1");  // Error — plain string isn't a UserId
declare const oid: OrderId;
getUser(oid);   // Error — OrderId and UserId are both branded strings, but distinct brands
```

The `unique symbol` brand only exists at the type level — there's no actual symbol at runtime, and the cast (`as UserId`) is required exactly once, at the boundary where the value is validated or constructed.

A simpler, more common variant uses a string-literal tag instead of `unique symbol` — easier to read, slightly less airtight (structurally identical brands using the same literal name can still collide across unrelated `Brand<T, "Name">` helpers if reused sloppily):

```ts title="index.ts"
type Brand<T, B extends string> = T & { readonly __brand: B };

type Email = Brand<string, "Email">;
type Password = Brand<string, "Password">;

function sendEmail(e: Email) {}

declare const email: Email;
sendEmail(email);       // ok
sendEmail("a@b.com");   // Error — raw string rejected
```

Common uses: IDs that shouldn't be mixed up (`UserId` vs `OrderId`), validated-vs-raw strings (`Email`, `NonEmptyString`), and units (`Meters` vs `Feet`). It's a compile-time-only technique — the brand adds zero runtime cost but also zero runtime enforcement, so still validate at the boundary where the branded value is created.
